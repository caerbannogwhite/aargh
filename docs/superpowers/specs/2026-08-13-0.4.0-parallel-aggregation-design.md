# 0.4.0 — Parallel Single-Pass Aggregation

**Date:** 2026-08-13
**Status:** Approved (brainstorming) — ready for implementation planning
**Theme:** 0.4.0 "make it fast" — the headline feature.

## Context

`GroupBy().Agg().Run()` is enchanter's aggregation path. Today it runs in **two
phases**:

1. `GroupBy()` **eagerly** builds a chain of `map[int64][]int` partitions (one
   per key column), in parallel (16-worker tree merge).
2. `Agg().Run()` then does a **single-threaded** second phase: for *each*
   aggregator, allocate a full `[]float64` (`__gdl_stats_preprocess`) and do a
   separate scatter pass over all rows (`stats.go`). `Std` double-passes;
   `Count` is inline from group sizes.

A throwaway 0.4.0 spike (`benchmarking/gospike/`) measured a pragmatic pure-Go
**single-pass, parallel hash-aggregation** for `sum(v1) by id1` on the h2oai G1
datasets and found it **9.6–17.3× faster** than the current path — and faster
than Polars on that query (~15.5 ms vs ~43.2 ms at 1e7 rows). The win comes from
(a) fusing grouping and aggregation into one pass (no materialized row-index
lists), (b) parallelizing that pass, and (c) hashing the **interned `*string`
pointer** instead of the string bytes (enchanter interns strings in a per-context
`StringPool`, so equal keys share one pointer).

This design generalizes that spike into the real `GroupBy().Agg()` — multi-key,
all aggregates, nulls, all supported types — as a drop-in speedup of the existing
API. It also fixes a latent multi-key **collision hazard** and modernizes null
and ordering semantics.

## Goals

- Fused, single-pass, parallel hash-aggregation behind the existing
  `GroupBy().Agg().Run()` API — realize the spike's speedup on real queries.
- **Correct** multi-key grouping (replace the current hash-mix-without-equality
  with exact composite-key equality).
- **Deterministic** output: result rows sorted by the group-by key(s).
- **Skip nulls by default** in aggregations, matching pandas/Polars/SQL/dplyr.
- Add `Variance` and `Quantile` aggregators; wire `Median` for real (currently
  defined but silently unhandled). Parameterize them with **functional options**:
  `WithInterpolation` (Median/Quantile) and `WithDDoF` (Std/Variance).
- Introduce a clean **internal** accumulator abstraction so the built-ins are its
  first implementations — the documented extension point for user-defined
  aggregators (public constructor deferred to 0.5.0).
- Remove the dead commented-out worker-pool aggregation code.

## Non-goals (explicitly out of scope)

- **Fused element-wise combinators** (`(a+b)>0 → filter`) — separate 0.4.0 spec.
- **Public** custom-aggregator API — designed-for here, exposed in 0.5.0 (the
  API-stabilization release).
- Changing aggregate **result types** (Count→`Int64`; Sum/Mean/Min/Max/Std/
  Variance/Median/Quantile→`Float64`) or the **supported input types**
  (numeric/bool/duration coerced to float64; others still error). Type-preserving
  `Min`/`Max` (e.g. keeping `Time`) is a future refinement.
- A general benchmark-regression-**tracking** framework (a separate roadmap item);
  this spec adds the aggregation benchmarks themselves, not the tracking infra.

## Deliberate behavior changes (approved breaks)

These change observable output; existing groupby tests are updated to match:

1. **Result row order** is now **sorted by the group-by key(s)** (was
   non-deterministic Go-map order). Multi-key = lexicographic over key columns;
   **nulls sort last**.
2. **Null values are skipped by default.** A null in an aggregated column no
   longer poisons its group's aggregate to `NaN`. The existing `RemoveNAs` knob
   is preserved: `.RemoveNAs(false)` restores NaN-poisoning, and that poisoning
   applies to **every** aggregate over a null-containing group — reducible and
   holistic (`Median`/`Quantile`) alike (`Count` excepted, since it counts rows,
   not values). (Null **keys** are unchanged: all null-key rows form one group.)

## Architecture (Approach A: lazy GroupBy + fused engine)

The eager partition is not exclusive to `Agg` — `Join` (`base.go:730-731`),
`groupHelper`, and several `isGrouped` guards consume it. So we keep partitions
available on demand while letting `Agg` bypass them:

- **`GroupBy(cols…)` becomes lazy.** It records the key column names and sets
  `isGrouped`, but builds **no** partitions.
- **`getPartitions()` / `groupHelper()` materialize on demand** (memoized on the
  frame). `Join`, `Ungroup`, and the `isGrouped` guards keep working unchanged —
  they simply trigger materialization the first time they need it.
- **`Agg(…).Run()` routes to the new engine**, which reads the recorded key
  columns and the raw series data and does grouping + aggregation in one fused
  pass — never materializing the `map[int64][]int` index lists.

## Components

### 1. Aggregator model

`AggregateType` splits into two families the engine treats differently:

- **Reducible** (constant per-group state, single pass): `Count`, `Sum`, `Mean`,
  `Min`, `Max`, `Std`, `Variance`, `Any`, `All`. Std/Variance use **Welford's** running mean/M²
  (numerically stable and parallel-mergeable via the standard pairwise-variance
  combine), with the divisor governed by `ddof` (below).
- **Holistic** (need all values): `Median`, `Quantile(p)`. These retain a
  per-group value slice; finalize sorts and selects with the configured
  interpolation.

**`Any` / `All` (bool reductions).** Reducible too — `Any` = OR over the group's
truthy values, `All` = AND — but they produce a **`Bools`** result column, not
`Float64` (a new result type, added for these new aggregates; existing aggregates'
types are unchanged). Input is a bool/truthy column (the engine already coerces
`Bools` → 0/1). Nulls are skipped by default; under `RemoveNAs(false)` a null makes
the group's result **null** (bool has no `NaN`, so poison surfaces as null, not
`NaN`). Empty / all-null group → null. Constructors: `Any(col)`, `All(col)`
(`any(x)`, `all(x)`).

**Parameters — functional options.** Per-aggregator parameters travel with the
aggregator (each `Quantile`/`Std` in one call can differ), set via variadic
options on the constructor: each constructor is
`func Name(col string, …, opts ...AggOption) aggregator`. The query-wide null
policy (`RemoveNAs`) stays on the builder — it is not per-aggregate.

```go
Sum("v1")
Std("v1", WithDDoF(1))                       // sample std; default ddof=0 (population)
Variance("v1", WithDDoF(1))
Quantile("v1", 0.25, WithInterpolation(Higher))
Median("v1", WithInterpolation(Midpoint))    // Median == Quantile(0.5)
```

- **`WithInterpolation(m)`** — `Median`/`Quantile`. Methods are the numpy/pandas
  standard set: `Linear` (default), `Lower`, `Higher`, `Nearest`, `Midpoint`
  (an exported `Interpolation` enum). `Median` defaults to `Linear`, which yields
  the conventional "average the two middles" for even counts.
- **`WithDDoF(d)`** — `Std`/`Variance`. Divisor is `n - d`; default `0`
  (population, matching today's `Std`), `1` for the sample estimator.

Constructors: existing `Count/Sum/Mean/Min/Max/Std`, plus **`Variance`**,
**`Quantile`**, and `Median` (now produces a column). Output column naming follows
the current convention (`sum(x)`, `std(x)`, `median(x)`; `quantile(x)` encodes
`p`, e.g. `quantile_0.25(x)`).

### 2. Accumulator / Collector abstraction (internal extension point)

An internal interface pair captures the two families' shape:

- A **reducible accumulator**: fresh per-group state supporting
  `update(value, isNull)`, `merge(other)`, and `result() → (float64, null)`.
- A **holistic collector**: `collect(value, isNull)`, `merge(other)`,
  `result() → (float64, null)`.

The built-ins are the **first implementations**. Two execution lanes keep this
free for the hot path:

- **Built-ins run as specialized, monomorphic loops** (a typed pass per
  aggregate — no per-row virtual dispatch), which is what preserves the spike's
  speed.
- The interface is the **abstraction and the fallback**: future user-defined
  aggregators (0.5.0) plug in here with one virtual `update` per row — flexible,
  modestly slower, and costing the built-ins nothing.

Kept **unexported** in 0.4.0 and documented as the 0.5.0 public extension point.
Prior art to review during implementation: the archived `archive/dev-fix-agg`
custom-aggregator attempt.

### 3. The engine (fused single-pass, parallel)

1. **Keys.** A single `Strings` key hashes the interned **`*string` pointer**
   (the spike trick). A multi-key groups on a **correct composite key**: each key
   column's distinct values are dense-coded per column and packed into a
   composite, giving exact equality — this replaces the current
   `value + MAGIC + (h<<13)+(h>>4)` mix that never re-checks equality on collision.
   On first sight of a group, capture its **representative key values** (for the
   result key columns and the final sort). Null-key rows collapse to one group.
2. **Parallel single pass.** Partition rows into `GOMAXPROCS` chunks (serial below
   a size threshold, mirroring today's `MINIMUM_PARALLEL_SIZE`). Each worker keeps
   a local `map[key]→gid` plus local accumulators/collectors and makes one pass
   over its chunk, assigning dense group ids and updating state.
3. **Merge.** Union worker key sets into a global group set, remap ids, and
   combine state: add sums/counts, min/max, **Welford pairwise-merge** for
   Std/Variance, concatenate holistic slices.
4. **Nulls.** Null values are skipped (state untouched) by default. Under
   `RemoveNAs(false)` a null poisons its (group, aggregate) result to `NaN`
   uniformly for every aggregate kind — a per-(group,aggregate) poison flag,
   OR-merged across workers, checked before finalize (`Count` excepted).
5. **Finalize + sort.** Compute each group's result. **Sort groups by key**
   (lexicographic across key columns, nulls last). Emit the result DataFrame:
   key columns first (group-by order), then one column per aggregator (aggregator
   order), one row per group, in sorted order.

### 4. Integration & cleanup

- Lazy `GroupBy`; memoized on-demand `getPartitions()`/`groupHelper()`.
- `Agg().Run()` routed to the engine; `Variance`/`Quantile` constructors added;
  `Median` wired.
- Remove the dead commented-out aggregation code (the worker-pool remnants in
  `aggregator.go:92-117` and `stats.go`). The disabled dense-map path in the
  *grouping* code is left alone — grouping is retained for the on-demand partition
  path (`Join`, `getPartitions`).

## Data flow

```
GroupBy(k…)         -> record key columns (lazy; no partition)
   |
Agg(a…).Run()
   |-- for each worker chunk (parallel):
   |     one pass: key -> gid (local map); update per-gid accumulators/collectors
   |-- merge worker states -> global groups + combined state
   |-- finalize per group  -> reducible: result(); holistic: sort+select
   |-- sort groups by key (nulls last)
   \-- build result: [key cols…][agg cols…], one row per group, sorted
```

## Error handling

- Unsupported input type for an aggregate → error series (as today).
- `Quantile` `p ∉ [0,1]` → error.
- An option applied to an aggregator that does not accept it (e.g. `WithDDoF` on
  `Sum`, `WithInterpolation` on `Mean`) → validation error surfaced in `Run()`.
- A group that is empty or all-null under skip-null semantics → null result for
  that group's value (not `NaN`).
- `Std`/`Variance` on a group with `n ≤ ddof` non-null values (e.g. sample std of
  a one-element group) → null result for that group.
- Duplicate output column names / missing input column → validated up front in
  `Run()`, as today.

## Testing & validation

- **Correctness (reference-based).** Expected values computed independently (not
  diffed against old output, since order and null defaults change on purpose):
  each aggregate across single- and multi-key, with and without null values and
  null keys, across all supported input types. Include a mixed reducible +
  holistic (`Median`/`Quantile`) query to exercise both lanes in one call.
- **Properties.** Σ group counts = nrows; Σ group sums = grand total; number of
  result rows = number of distinct keys; sorted order is verified.
- **Benchmarks.** Port the spike's G1 `Q1` (`sum(v1) by id1`) into the real path
  to confirm the win vs `v0.3.0` and vs Polars; add a multi-key + multi-aggregate
  case. (Fixtures are the gitignored `testdata/G1_*`; benchmarks skip when absent,
  as the spike does.)
- **Regression.** Update the existing `dataframe` groupby/aggregation tests to the
  new sorted-order and skip-null semantics.
